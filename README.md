# Uponor Smatrix X-265 for Homey

A Homey app that adds each room of an Uponor Smatrix Pulse floor heating system as a sensor in Homey. Each room shows its temperature, plus humidity if its thermostat has a humidity sensor.

It reads data from the Uponor **R-208** communication module over your local network. It does not use the Uponor cloud and needs no login.

- App id: `com.tobiasfagerskog.uponor-smatrix_x-265`
- Runtime: Python 3.14, Homey Pro 2023 or newer on firmware 13.0.0 or later

## What you get

- **One device per room thermostat.** Devices are named after the room names set in the Uponor system, for example "Kontor 1.10". A room without a name is called "Room C1T10" (controller 1, thermostat 10).
- **Temperature** for every room, and **humidity** for rooms whose thermostat has a humidity sensor.
- **Poll interval** in the app's settings (10–3600 seconds, 60 by default). The one value applies to every room, and changing it takes effect right away.
- If the gateway can't be reached, the rooms show as unavailable with the error message. They recover by themselves on the next successful poll.

## Requirements

- An Uponor Smatrix Pulse system (X-265 wireless or X-245 wired controller) with an R-208 communication module on the same network as your Homey.
  The app has only been tested with an X-265 controller and an R-208 module. It should work with the X-245, but that is untested.
- The R-208's IP address. You can find it in your router's list of connected devices; it identifies itself as `UPONOR.PULSE.<id>`. Give it a fixed IP address (a DHCP reservation in your router), because the app stores the address when you add the rooms.
- To build it yourself: the Homey CLI (`npm install -g homey`).
- To build it yourself: **Docker running** on the machine you develop on. The CLI builds and runs Python apps in Athom's Docker images (`ghcr.io/athombv/python-homey-app-runner`).

## Install and run

Install **Uponor Smatrix X-265** from the Homey App Store, or build it from source:

```sh
homey app run       # run in development mode, with logs in the terminal
homey app install   # or install it permanently
```

## Adding rooms

1. In the Homey app, go to **Devices → + → Uponor Smatrix X-265 → Room Thermostat**.
2. Enter the R-208's IP address. The app contacts the gateway right away, so a wrong address fails at this step.
3. Pick the rooms you want to add. Each one becomes its own sensor.

To change the poll interval, open **Settings → Apps → Uponor Smatrix X-265 → Configure app**.

## How it works

The R-208 has a small local HTTP interface called JNAP. The app sends a `POST` request to `http://<host>/JNAP/` with the header `x-jnap-action: http://phyn.com/jnap/uponorsky/GetAttributes` and an empty JSON body. The reply is a flat list of variables. This protocol was worked out from the [uponorx265](https://github.com/dave-code-ruiz/uponorx265) Home Assistant integration.

The app reads these variables for each room (`C<controller>_T<thermostat>`):

| Variable | What it holds |
|---|---|
| `C1_T1_room_temperature` | Room temperature in tenths of °F. Converted to °C as `(raw - 320) / 18`. |
| `C1_T1_rh` | Relative humidity in %. `0` means the thermostat has no humidity sensor. |
| `cust_C1_T1_name` | The room name set in the Uponor system. |

Each device polls on its own, so every poll interval makes one request per room.

## Development notes

- **Edit `.homeycompose/app.json`, not `app.json`.** The CLI rebuilds `app.json` and `.homeybuild/` from the compose files. `.homeybuild/` is listed in `.gitignore`.
- **Imports must be relative.** The runner loads the app as a package called `app`, and it has its own `lib` package on the import path. Import with `from ...lib.uponor import ...`, not `from lib.uponor import ...`.
- **No Python packages needed.** The app uses only the standard library, so `pythonPackages` in the manifest stays empty. Blocking HTTP calls run in a thread (`asyncio.to_thread`) so they don't stall the app.
- **Timers:** `homey.set_interval` calls its callback once right away, so a device doesn't poll separately at startup.
- **The settings page must load `/homey.js` itself.** Put `<script src="/homey.js" data-origin="settings"></script>` in its `<head>`. Pairing screens get this script automatically, but the settings page does not. Without it the page shows a loading spinner forever and logs no error.
- **Checking the gateway by hand:** `curl -X POST http://<host>/JNAP/ -H 'x-jnap-action: http://phyn.com/jnap/uponorsky/GetAttributes' -d '{}'` prints every raw variable the gateway returns. On a Mac, if Python gets `No route to host` while `curl` reaches the gateway, allow Local Network access for your terminal under System Settings → Privacy & Security → Local Network.
- **Store text lives in `README.txt`** (plain text, no URLs) and release notes in `.homeychangelog.json`. This `README.md` is for GitHub only.

## Continuous integration

GitHub Actions in `.github/workflows/`:

- **Validate** runs Athom's validate action at the `verified` level on every push and pull request.
- **Update version** (run by hand) bumps the version with Athom's version action, adds the changelog entry, then commits, tags and creates a GitHub release.
- **Publish** (run by hand, or when a GitHub release is published) uploads the build to the Homey developer dashboard. It needs a `HOMEY_PAT` repository secret, the personal access token from https://tools.developer.homey.app/me. Athom's publish action can't be used because it runs `npm ci`, which fails for a Python app, so the workflow runs the same `homey app publish` command directly.

Publishing only uploads a draft build. Releasing it to Test or submitting it for certification is still done in the developer dashboard.
